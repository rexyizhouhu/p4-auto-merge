# P4 自动合并工具

双击 [Start.cmd](./Start.cmd)。依赖 Windows 自带 PowerShell 5.1、Windows Forms，以及已经安装并登录的 `p4.exe`；手动 Resolve 使用已安装的 P4V。

分发版使用单个 `P4AutoMerge.exe`，界面与核心脚本均内置。完整解压发布 ZIP 后双击 EXE 即可；仍需 Windows x64、PowerShell 5.1 / .NET Framework 4.8、已安装并登录的 P4 和 P4V。EXE 不包含用户身份、workspace 配置、队列或 P4 安装程序。内置脚本按内容摘要缓存在当前用户 LocalAppData 中，脚本路径不依赖 ZIP 所在位置或启动目录，更新不会混用不同版本的脚本。

安装版双击 `P4AutoMerge-<版本>-Setup-x64.exe`，按中文向导选择目录。默认按当前用户安装到 `%LOCALAPPDATA%\Programs\P4AutoMerge`，桌面快捷方式默认勾选，也会添加开始菜单入口；可在 Windows“已安装的应用”里卸载。无需管理员权限。卸载移除程序及快捷方式，保留 `%LOCALAPPDATA%\FlamesTools\P4AutoMerge` 的队列和诊断；升级或卸载前先等待自动处理完成并关闭工具。

本工具仅在本地保留，不加入 P4；目录内的 [.p4ignore](./.p4ignore) 防止常规添加或 reconcile 意外登记工具文件。运行错误在状态栏和“运行日志”显示，不弹出错误对话框。确认执行合并等需要用户主动选择的提示仍会显示。

## 使用步骤

1. 启动后自动连接并加载 workspace；修改服务器/用户或需要刷新时，点击“连接 / 刷新 workspace”。工具使用当前 P4 登录身份，默认服务器为 `192.168.60.201:1666`，Unicode 编码为 UTF-8。
2. 选择目标 workspace。界面显示它的本地目录和实际分支。注意名称含 Main 的 workspace 也可能绑定 Release，以实际显示为准。未选择来源时，目标列表为空且禁用。
3. 选择来源分支后，默认只显示直接父子分支中方向允许 merge 的目标。需要合并到其他同仓库分支时，明确勾选“允许跨分支合并”；此时显示同 depot 的其他实体 stream，不包括来源自身、其他 depot 或虚拟 stream。即使 P4 的 `--from` 允许某些非父子方向，工具也仅在勾选后显示这些额外目标。取消勾选会移除额外目标并清除不再有效的选择；目标仍必须与 workspace 实际 stream 一致，工具不修改 workspace 配置。
4. 选择目标，点击“加载来源 CL”。默认加载最近 1000 条，可调低。在搜索框输入 CL 编号、提交人或描述中的文字，即时筛选已加载的 CL；忽略英文大小写，描述使用完整内容。搜索只覆盖当前加载的条目，上限 1000；超出范围的已知 CL 可在下方手动输入编号。筛选和清除搜索都会保留已勾选 CL，右侧显示当前显示/已加载/已勾选数量；被搜索隐藏的勾选项仍会包含在预览和合并请求里，切换来源分支则清空旧分支勾选。
5. 勾选 CL，或在列表下方输入编号，逗号、空格、换行均可。输入与勾选结果合并、去重、升序执行；不接受编号区间。
   已经合入、后来又撤销的 CL，需要重新合入时，可勾选“强制重新合并（忽略本次全部所选 CL 的合并历史）”。此开关默认关闭，作用于本次全部所选 CL；如果只想重合某一个 CL，请单独选择它。它不增加可选目标，与“允许跨分支合并”独立。改变开关后必须重新预览。
   点击“查看已选 CL”或“已选 CL”页签，集中查看勾选与手动输入合并去重后的编号和实际合并顺序。已加载的 CL 显示提交人及说明，搜索隐藏的勾选项也会列出；未加载的手动编号明确标记缺少详情。该视图仅整理当前选择，仍需点击“1. 预览”执行 P4 的提交状态、来源和文件检查。活动队列显示其已保存编号。最多显示 1000 个 CL、每条说明最多 500 字符，超限明确提示，实际选择和请求不截断。
6. 点击“1. 预览”，查看方向、CL 和文件。预览只读，不创建 pending CL。所有 CL 是各自独立预览，后续 CL 的实际结果还取决于前面的合并和手工处理。
7. 点击“2. 执行合并”，核对确认框。工具重新检查后新建一个 pending CL，按源 CL 升序执行 merge，并对该 pending CL 执行安全 Resolve。
8. 如果还有待手工处理项目，队列停止在当前源 CL。点击“在 P4V 打开 workspace”，找到界面给出的 pending CL，在 P4V 执行 Resolve。保存编辑后的文件还不够，必须在 P4V 中确认 Resolve 结果，直到该 CL 没有未解决项。
9. 回到工具点击“检查并继续”。只有当前 CL 的所有 Resolve 项都处理完成，才会合并后续源 CL。整个队列完成后，自行检查和提交 pending CL。

列表中的长描述显示前 200 字和省略号；完整描述仍参与搜索，也可将鼠标停在该条目上查看提示。更新脚本后请关闭旧工具并重新启动，已打开的窗口不会自动更新。

来源 CL 数量默认 1000。来源列表/操作按钮与下方预览之间有水平分隔条，按住分隔条上下拖动，可调整列表与预览的高度；“已选 CL”、文件预览和运行日志共用该可调整区域。

## 合并语义

- 每个源 CL 使用精确范围 `@CL,CL`。例如选 101、103，分别处理 101 和 103，不会把它解释成 101–103 的连续范围。选中 CL 若依赖未选中修改，仍需要人工判断合并结果。
- 未勾选跨分支时使用普通父子模式，命令为 `p4 merge -Af -c <pending> --from //来源 //目标/...@CL,CL`，由 P4 再次执行正常合并方向检查，`-Af` 仅合并文件，不合并 stream 定义。工具主动将默认候选限制为直接父子关系，且排除需要 copy 的方向；这不是 P4 `--from` 所有可用方向的完整列表。候选不代表文件映射或权限一定可用，仍以真实预览/执行结果为准。
- 只有勾选跨分支时才使用 `p4 merge -F -c <pending> //来源/...@CL,CL //目标/...`，允许同仓库中用户明确选择的其他方向。仍遵守已记录的合并历史，不使用忽略合并历史的强制重合并选项。跨分支模式针对路径相同的文件，不提供自定义 branch spec 或不同目录之间的映射。
- 上述 `merge` 命令用于未开启“强制重新合并”的情况。开启后改用 `integrate -f -Rbd -Or -Af`，忽略所选精确修订范围的合并历史；`-Rbd` 保留新增/删除的 Resolve，自动处理仍只有 `resolve -as`。普通父子目标使用 `-S //目标 -P //来源 -r //目标/...@CL,CL` 的 stream 映射；跨分支开关开启时才改用 `-F //来源/...@CL,CL //目标/...` 的路径映射。已有目标范围及映射、workspace、未 checkout 修改等检查仍执行。该选项不会直接以来源版本覆盖目标，也不会自动提交。
- 预览显示 0 个文件时，会在该 CL 下显示 P4 返回的原因，例如 `All revision(s) already integrated`。这表示 P4 记录中已集成，不能据此断言当前目标仍含修改；后续撤销不会删除这份历史。强制重合并只把指定修订重新交给 Resolve，不能保证业务依赖齐全或编译通过。
- 普通父子模式保守拒绝存在 `isolate`（仅本分支使用的路径）或 `Remapped`（目录重映射）的 stream，包含它们实际继承的祖先配置，避免 P4 静默排除部分文件后误报整个 CL 完成。遇到这些配置会明确停止，不会自动启用跨分支模式；需先人工核对映射和所选文件范围。
- 自动 Resolve 仅使用 `p4 resolve -as -c <pending>`。只在安全条件下接受已有一侧的内容，跳过需要合并内容的文件。不使用 `-am`、`-af`、`-at` 或 `-ay`。所以无行冲突但两侧都修改过的文件也可能需要手工处理。
- 操作范围是所选来源 stream 自身的 depot 路径，不包含 stream 导入的 SDK 等外部 depot 路径。跨多个来源分支的 CL 会被拒绝，避免只合入部分内容而误报完整成功。
- 不执行 `submit`、`sync`、`revert` 或编译。P4 的 merge 命令自身可能按其正常语义更新相关目标文件。必须使用干净的合并 workspace：已有 opened 文件、相关路径未 checkout 的本地新增/修改/删除会阻止开始。检查包含精确目标映射以及 P4 根据历史重命名选出的实际目标，每个源 CL 执行前重新检查。
- workspace 映射排除所选文件或出现未识别的 P4 警告时停止，避免将只合入部分文件误报为成功。自动操作期间请勿在其他工具操作同一 workspace；工具自身按本地根目录互斥，但不控制独立运行的 P4V / P4 命令。
- 大 CL 的预览、待处理列表只在界面显示前 2000 个文件明细，实际队列不截断；预览额外显示最多 50 条 P4 原因消息，每条最多 1000 字符并合并换行，超限显示省略数量。运行日志保留最近约 50 万字符。请在 P4V 查看完整 pending CL。

## 中断与恢复

队列状态保存在当前 Windows 用户的 `%LOCALAPPDATA%\FlamesTools\P4AutoMerge`，按 P4 服务器、用户和 workspace 分开存放。关闭工具不会自动回滚合并结果。

重新启动后连接相同服务器和用户，选择原 workspace，点击“恢复该 workspace 队列”。等待手工 Resolve 的队列可以继续；自动 Resolve 中断可以重新检查并继续。

队列会保存跨分支开关，恢复时显示原选择并锁定，不会因当前界面开关而改变已保存队列的范围。旧版本未保存开关的队列按普通模式处理，不会自动获得强制合并权限；如果旧方向不符合普通合并规则，请结束跟踪后在 P4V 核对并自行完成。

强制重新合并开关同样随队列保存，恢复时沿用且锁定，不能在队列中途改变模式。旧队列缺少此字段时默认关闭。发生结果不确定的错误时，即使开启强制重合并也不会自动重放上次操作。

手工阶段请使用 Resolve，不要 revert 队列中的文件。工具会核对文件仍在原 pending CL；文件消失或移动到其他 CL 时停止继续。若你确实要丢弃部分合并，或手工改名使文件集合改变，请在 P4V 核对并“结束队列（保留 CL）”，之后自行完成该批处理。

如果退出或报错时 merge 的结果无法确定，工具会保留该 pending CL 并禁止自动重试。先在 P4V 核对并自行完成或放弃这个 pending CL。可点击“结束队列（保留 CL）”结束工具跟踪；该操作只更新本地队列记录，不修改 P4 文件。开始下一轮前 workspace 仍需干净。不要通过重复点击执行来恢复不确定的写操作。

## 验证与开发

运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-P4AutoMerge.ps1` 执行模拟 P4 命令及本地输入字节测试，不连接 P4 服务器，不执行真实合并。字节测试使用隐藏的 PowerShell 子进程回传实际收到的数据，验证中文表单、空输入均不会多出 UTF-8 标记，以及启动失败后原编码恢复。

P4 表单通过无标记 UTF-8 输入。Windows PowerShell 5.1 使用的 .NET Framework 会在启动子进程时建立输入写入器；工具在该步骤临时指定无标记编码，启动后立即恢复，并在工具进程内串行执行这一步。脚本文件本身仍保留 UTF-8 BOM，供 PowerShell 5.1 正确识别中文。

运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-P4AutoMerge.ps1 -ReadOnlyConnection` 只查询当前身份、workspace 和 stream 列表。

运行 `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\P4AutoMerge.ps1 -SmokeTest` 创建并检查实际 Windows Forms 控件，随后关闭界面。

运行 `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\P4AutoMerge.ps1 -HeadlessTest` 在不显示窗口、不发送鼠标键盘操作的情况下检查控件、队列按钮、大列表限制和切换身份时的状态。

运行 `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\P4AutoMerge.ps1 -ReadOnlyStartupTest` 在隐藏界面中执行实际的启动连接流程，检查 workspace 已加载且自动选中；只查询 P4，不执行合并或 Resolve。

内部排查记录不包含在公开源码中。安装包请在本仓库 Releases 页面下载。

## 构建分发包

只有用户明确授权构建本工具 EXE 时，才运行 [Build-Release.ps1](./Build-Release.ps1)。它调用 Windows 自带 .NET Framework C# 编译器，仅构建 [Launcher.cs](./Launcher.cs)，把已验证的界面及核心脚本嵌入 EXE；不调用项目、引擎或插件构建。每次输出到 Releases 下新的时间戳目录，生成全新 ZIP，不覆盖已有包，也不自动加入 P4。

包中仅有 EXE、使用说明、版本信息、SHA256 校验和与本地忽略规则。启动器以普通用户权限运行，PowerShell 控制台隐藏，正常工具窗体照常显示；运行时不联网下载组件，不修改持久化执行策略。当前 EXE 未进行代码签名。

使用 [Test-Release.ps1](./Test-Release.ps1) 的 `-ZipPath` 指定压缩包，验证允许的发布文件、校验和、x64 GUI 文件格式及内置源码，然后在中文且含空格的解压目录运行 EXE 的隐藏自测和实际只读启动。验证不执行真实合并。测试解压文件保留在 Temp 的独立 ReleaseTest 目录，便于复查。

安装包构建使用 [Build-Installer.ps1](./Build-Installer.ps1) 的 `-PackageDirectory` 指定已经验证的便携版目录；安装规则在 [Installer.iss](./Installer.iss)。构建依赖官方签名验证通过的 Inno Setup 编译器，接收者不需要安装编译器。发布载荷只列入已知五个文件，哈希由 [Packaging.Common.ps1](./Packaging.Common.ps1) 统一生成。安装包输出到新的 Installer 时间戳目录，同时提供 Setup EXE 和分发 ZIP。

[Test-Installer.ps1](./Test-Installer.ps1) 用同一安装脚本编译隔离测试变体，仅变更测试 AppId、显示名和快捷方式目标目录。它在 Temp 下完成安装、原位升级、卸载、桌面选项取消、运行中阻止安装，以及安装后 EXE 隐藏自测；桌面和开始菜单快捷方式均重定向到测试目录，卸载注册项使用一次性标识，完成后删除。测试保留非安装器所有的文件，并不触碰真实 P4 队列或执行合并。
